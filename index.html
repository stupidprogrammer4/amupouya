Inventory. Orders. Pricing.

Commerce infrastructure · Goldis

Many marketplaces.
One coherent system.

A synchronization and pricing engine that connects products, inventory, orders, discounts, and invoices across four marketplaces.

The work spans concurrent workers, competitor-aware pricing, product mapping, and financial reporting — with explicit limits and recovery paths when an external service misbehaves.

  • Python
  • Litestar
  • Taskiq
  • PostgreSQL
  • Redis
A closer look +

Workers propagate marketplace changes asynchronously. Automatic, competitive, and takeover pricing modes share stop-loss constraints. Product mapping connects external listings to internal inventory, while a custom ORM path supports database-intensive operations.

04 / How I think

The tools change.
The questions stay.

What happens under load? Where does failure go? Will the next person understand this?

01

Make the boundaries clear.

Typed interfaces, explicit dependencies, and modules that each have a job.

02

Think about the unhappy path.

Retries, cancellation, cleanup, and observability belong in the design.

03

Choose tools for the problem.

Python for most backends. PostgreSQL for persistence. Queues when work needs its own pace.
